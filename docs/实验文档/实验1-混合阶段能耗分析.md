### 1.2 GPU 频率效应

| GPU 频率 | 平均功耗 (W) | E/token (J) | 吞吐 (tok/s) |
|:---:|:---:|:---:|:---:|
| 306 MHz | 16.2* / 42.7** | 1.423* / 1.215** | 11.7* / 38.9** |
| 612 MHz | 42.2 | **1.187** | 38.6 |
| 918 MHz | 42.0 | 1.339 | 36.7 |
| 1300 MHz | 43.2 | 1.194 | 39.1 |

\* GPU306_CPU1036 (CPU 最低频时 GPU 306MHz 成为瓶颈)
\** 排除 CPU1036 后的平均值

**关键发现**：
- GPU 306MHz 在 CPU ≥ 1497MHz 时吞吐量与高频 GPU 持平（~39 tok/s），说明 GPU 306 在 decode 阶段足够
- GPU 306MHz + CPU 1036MHz 组合下吞吐量骤降至 11.7 tok/s，但这是因为 CPU 太慢导致 GPU 调度延迟
- GPU 612MHz 是全局能效最优点（1.187 J/token）
- GPU 918MHz 吞吐略低于 612MHz，可能与调度开销有关

### 1.3 CPU 频率效应

| CPU 频率 | 平均功耗 (W) | E/token (J) | 吞吐 (tok/s) |
|:---:|:---:|:---:|:---:|
| 1036 MHz | 35.7 | 1.286 | 31.2 |
| 1497 MHz | 42.8 | **1.206** | 39.0 |
| 2201 MHz | 43.7 | 1.235 | 39.3 |

**关键发现**：
- CPU 1497MHz 是能效最优点（1.206 J/token）
- CPU 2201MHz 功耗增加 1W 但吞吐几乎不变（39.3 vs 39.0 tok/s）
- CPU 1036MHz 吞吐下降 20%，功耗下降 7W，E/token 反而变差

### 1.4 功耗域分解

| CPU 频率 | 总功耗 | GPU SoC | CPU CV | SYS 5V0 |
|:---:|:---:|:---:|:---:|:---:|
| 1036 MHz | 35.7W | ~4.0W | ~6.3W | ~5.6W |
| 1497 MHz | 42.8W | ~4.0W | ~7.5W | ~6.0W |
| 2201 MHz | 43.7W | ~4.3W | ~7.8W | ~6.4W |

GPU SoC 功耗在不同 CPU 频率下变化很小（3.8-4.3W），说明 GPU 计算在混合阶段占比有限。

### 1.5 负载维度

各 workload 在不同配置下的最优能效：

| Workload | 最优配置 | tok/J | 吞吐 (tok/s) |
|----------|---------|:---:|:---:|
| short_short (128→64) | GPU612_CPU1036 | 0.92 | 38.2 |
| short_long (128→256) | GPU612_CPU1036 | 0.87 | 39.0 |
| medium_medium (512→128) | GPU612_CPU1036 | 0.82 | 38.6 |
| long_medium (1024→128) | GPU612_CPU1036 | 0.79 | 38.6 |
| long_long (1024→512) | GPU612_CPU1036 | 0.81 | 39.0 |

**所有 workload 的最优配置一致：GPU612 + CPU1036**

## 分析结论

1. **GPU 612MHz 是混合推理的能效最优点**，提供接近最高吞吐量同时功耗最优
2. **CPU 1497MHz 是 CPU 能效甜点**，但 GPU612 + CPU1036 整体能效更好（因总功耗更低）
3. **GPU 306MHz 在 CPU ≥ 1497MHz 时吞吐量不降**，说明 decode 阶段 GPU 306 已足够
4. **功耗主体在 CPU 和系统域**（~12W），GPU 仅 ~4W，意味着降低 GPU 频率对总功耗影响有限
