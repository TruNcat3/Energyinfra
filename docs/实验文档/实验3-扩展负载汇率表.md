# 实验 3：扩展负载汇率表

> 本实验在修正 GPU governor 缺陷后重新采集数据，是当前有效的基准汇率表实验；
> 此前的 [实验 1](实验1-混合阶段能耗分析.md) 与 [实验 2](实验2-分阶段能耗分析.md) 中受 governor bug 影响的 GPU 频率相关结论以本实验为准。

**日期**：2026-05-15  
**状态**：已完成（672 runs）

---

## 实验设计

### 目的

用修正后的 `performance` governor 重新收集 14 种负载下的完整能耗数据，构建覆盖全部 workload × phase 组合的可靠能耗汇率表（rate table）与 DVFS 规则。

### 前置修正

本实验之前相继发现并修复了两个测量缺陷，否则频率—能耗关系会被系统性扭曲：

1. **CPU-only 推理（2026-05-14 修正）**：早期构建的 llama-cpp-python 未编译 CUDA 支持，所有推理实际运行在 CPU 上（`llama_supports_gpu_offload() = False`）。
2. **GPU governor 失锁（2026-05-15 修正）**：`userspace` GPU governor 在推理负载下无法锁定频率，GPU 自发跳频至 1300 MHz，导致实验 1/2 得出 "GPU 频率无影响 / 612 MHz 即饱和" 的错误结论。本实验改用 `performance` governor。

### 实验矩阵

| 维度 | 取值 |
|------|------|
| GPU 频率 | 4 档（306 / 612 / 918 / 1300 MHz） |
| CPU 频率 | 2 档（1036 / 2201 MHz） |
| Workloads | 14 种（覆盖 64→2048 tokens 输入/输出组合） |
| Phases | 2（mixed / decode） |
| Repeats | 3 |
| **总运行数** | **4 × 2 × 14 × 2 × 3 = 672 runs** |

## 实验结果

### GPU 频率对性能的影响（修正后）

以 decode 阶段、CPU=1036 MHz 为例：

| GPU 频率 | Decode 吞吐 | GPU SoC 功耗 |
|:---:|:---:|:---:|
| 306 MHz | ~12 tok/s | ~8 W |
| 612 MHz | ~23 tok/s | ~13 W |
| 918 MHz | ~30 tok/s | ~19 W |
| 1300 MHz | ~41 tok/s | ~30 W |

GPU 频率对吞吐的影响显著且单调：306→918 MHz 吞吐提升 2.5×。

### DVFS 最优配置

按阶段与输出长度分桶后，能耗—性能最优配置呈清晰规律：

| 阶段 | 负载特征 | 最优 GPU | 最优 CPU | 理由 |
|------|---------|:---:|:---:|------|
| Mixed | output ≤ 64 tokens | 612 MHz | 1036 MHz | 低功耗即可满足短输出 |
| Mixed | output ≥ 128 tokens | 918 MHz | 1036 MHz | 高吞吐摊薄功耗 |
| Decode | output ≤ 64 tokens | 612 MHz | 1036 MHz | 能效最优 |
| Decode | output ≥ 128 tokens | 918 MHz | 1036 MHz | 吞吐优先 |

GPU 918 MHz 在 14 个负载中的 10 个上为最优配置；CPU 1036 MHz 在全部桶中已足够，更高 CPU 频率无收益。

## 分析结论

1. **GPU 频率显著影响性能与能耗**：306→918 MHz 吞吐提升 2.5×，实验 1/2 的"无影响"结论系 governor bug 所致
2. **GPU 612 MHz 适合短输出**：低功耗下吞吐已足够，能效最优
3. **GPU 918 MHz 适合长输出**：14 个负载中 10 个的最优配置
4. **Decode 仍是功耗主体**：占推理总功耗约 73%，是 DVFS 优化的主要目标
5. **汇率表与 DVFS 规则**：基于 672 runs 构建了 28 个 workload × phase 桶的完整汇率表和 DVFS 规则，作为后续 rate table 体系（Phase 6 细粒度、Phase 11 workload-aware 表）的基础
