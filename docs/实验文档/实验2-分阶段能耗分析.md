# 实验 2：分阶段能耗分析

**日期**：2026-05-14
**数据文件**：`data/energy_profiling/energy_profiling_20260514_042505.csv`
**有效 runs**：345/360（prefill 165/180，decode 180/180）

## 实验设计

将混合推理拆分为 prefill 和 decode 两个独立阶段分别测量：

| 阶段 | 实现方式 | 测量重点 |
|------|---------|---------|
| **prefill** | output_length=1，只生成 1 个 token | TTFT = prefill 计算延迟 |
| **decode** | prompt_length=16（最小化 prefill），output_length=64-512 | TPOT = decode 每token延迟 |

**矩阵**：4 GPU × 3 CPU × 5 workload × 2 phase × 3 repeat = 360 runs

> **注意**：部分配置（GPU612/918 × CPU1497/2201，GPU306 × CPU2201）数据缺失，
> 实际覆盖 12 个配置组合中的 8 个。

## 实验结果

### 2.1 阶段总体对比

| 指标 | Prefill | Decode | 比值 |
|------|:---:|:---:|:---:|
| TTFT (ms) | 75.3 | 31.4 | 2.4× |
| TPOT (ms) | 75.4 | 29.3 | 2.6× |
| 吞吐 (tok/s) | 27.5 | 38.5 | 0.7× |
| 功耗 (W) | 14.5 | 40.2 | 0.4× |
| E/token (J) | 7.319 | 1.178 | 6.2× |
| GPU SoC (W) | 8.4 | 29.8 | 0.3× |
| CPU CV (W) | 1.0 | 1.0 | 1.0× |
| SYS 5V0 (W) | 5.2 | 9.4 | 0.6× |

**关键发现**：
- Decode 阶段功耗是 prefill 的 **2.8 倍**（40.2W vs 14.5W）
- Decode 阶段 GPU SoC 功耗是 prefill 的 **3.5 倍**（29.8W vs 8.4W）
- Prefill 阶段 E/token 是 decode 的 **6.2 倍**（7.319J vs 1.178J）
- 两阶段 CPU 功耗几乎相同（~1.0W），说明 CPU 不是功耗差异来源

### 2.2 Prefill 阶段：各配置性能

| 配置 | GPU (MHz) | CPU (MHz) | TTFT (ms) | 功耗 (W) | E/token (J) |
|------|:---:|:---:|:---:|:---:|:---:|
| GPU306_CPU1036 | 306 | 1036 | 216.2 | 10.3 | 7.03 |
| GPU306_CPU1497 | 306 | 1497 | 61.9 | 14.3 | 7.16 |
| GPU612_CPU1036 | 612 | 1036 | 63.5 | 14.1 | 5.87 |
| GPU918_CPU1036 | 918 | 1036 | 63.6 | 14.5 | 7.52 |
| GPU1300_CPU1036 | 1300 | 1036 | 63.5 | 14.7 | 7.57 |
| GPU1300_CPU1497 | 1300 | 1497 | 62.0 | 15.1 | 6.74 |
| GPU1300_CPU2201 | 1300 | 2201 | 61.0 | 16.1 | 7.95 |

**关键发现**：
- GPU 306MHz + CPU 1036MHz 时 TTFT 飙升至 216ms（GPU 成为严重瓶颈）
- GPU ≥ 612MHz 后 TTFT 稳定在 ~62ms，进一步提高 GPU 频率无明显收益
- GPU 612MHz 在 CPU 1036MHz 时 E/token 最低（5.87J），但样本较少（仅 3 runs/workload 有效）
- Prefill 阶段 GPU SoC 功耗：306MHz → 6.6W, 612+MHz → ~8.7W（差异仅 2W）

### 2.3 Decode 阶段：各配置性能

| 配置 | GPU (MHz) | CPU (MHz) | TPOT (ms) | 功耗 (W) | E/token (J) | tok/J |
|------|:---:|:---:|:---:|:---:|:---:|:---:|
| GPU306_CPU1036 | 306 | 1036 | 82.0 | 16.3 | 1.360 | 0.74 |
| GPU306_CPU1497 | 306 | 1497 | 24.5 | 42.0 | 1.151 | 0.87 |
| **GPU612_CPU1036** | **612** | **1036** | **24.7** | **41.3** | **1.113** | **0.88** |
| GPU612_CPU1497 | 612 | 1497 | 24.4 | 42.3 | 1.150 | 0.87 |
| GPU612_CPU2201 | 612 | 2201 | 24.3 | 43.1 | 1.176 | 0.85 |
| GPU918_CPU1036 | 918 | 1036 | 24.7 | 41.8 | 1.147 | 0.87 |
| GPU918_CPU1497 | 918 | 1497 | 24.5 | 42.3 | 1.161 | 0.86 |
| GPU918_CPU2201 | 918 | 2201 | 24.3 | 43.2 | 1.181 | 0.85 |
| GPU1300_CPU1036 | 1300 | 1036 | 24.8 | 41.9 | 1.152 | 0.87 |
| GPU1300_CPU1497 | 1300 | 1497 | 24.5 | 42.4 | 1.161 | 0.86 |
| GPU1300_CPU2201 | 1300 | 2201 | 24.3 | 43.4 | 1.191 | 0.84 |

**关键发现**：
- **GPU 612MHz + CPU 1036MHz 是 decode 阶段的全局能效最优配置**（1.113 J/token, 0.88 tok/J）
- GPU ≥ 612MHz 后 TPOT 稳定在 ~24.5ms，GPU 918/1300 无额外收益
- GPU 306MHz 在 CPU ≥ 1497MHz 时 TPOT 也为 ~24.5ms，但 GPU SoC 功耗仅 20W vs 32W
- CPU 频率对 decode 吞吐影响有限：CPU 1036→2201 功耗增加 2W 但 TPOT 仅改善 0.4ms

### 2.4 GPU 频率效应（按阶段）

| GPU 频率 | Prefill TTFT (ms) | Prefill GPU SoC (W) | Decode TPOT (ms) | Decode GPU SoC (W) | Decode E/token (J) |
|:---:|:---:|:---:|:---:|:---:|:---:|
| 306 MHz | 139.0* | 6.6 | 53.3** | 20.1 | 1.255 |
| 612 MHz | 63.5 | 8.6 | 24.7 | 31.3 | **1.134** |
| 918 MHz | 63.6 | 8.8 | 24.7 | 31.7 | 1.147 |
| 1300 MHz | 62.3 | 8.7 | 24.4 | 31.8 | 1.168 |

\* GPU306 + CPU1036 数据拉高平均值；CPU≥1497 时 TTFT=61.9ms
\** GPU306 + CPU1036 数据拉高平均值；CPU≥1497 时 TPOT=24.5ms

**关键发现**：
- **Prefill 阶段**：GPU 306→612MHz TTFT 降低 54%（139→63ms），但 612→1300 几乎无变化
- **Decode 阶段**：GPU 306→612MHz TPOT 降低 54%（53→25ms），612→1300 无变化
- **GPU SoC 功耗跃变**：306→612MHz 时 decode GPU 功耗从 20W 跃升至 31W（+55%）
- **两阶段均在 GPU 612MHz 处达到饱和**，更高频率只增加功耗不提升性能

### 2.5 CPU 频率效应（按阶段）

| CPU 频率 | Prefill TTFT (ms) | Prefill 功耗 (W) | Decode TPOT (ms) | Decode 功耗 (W) | Decode E/token (J) |
|:---:|:---:|:---:|:---:|:---:|:---:|
| 1036 MHz | 101.7 | 13.4 | 43.8* | 35.3 | **1.153** |
| 1497 MHz | 61.9 | 14.7 | 24.5** | 42.2 | 1.156 |
| 2201 MHz | 61.0 | 15.5 | 24.3 | 43.2 | 1.181 |

\* GPU306_CPU1036 拉高平均值；排除后 TPOT=25.0ms
\** GPU306_CPU1497 拉高平均值；排除后 TPOT=24.4ms

**关键发现**：
- **Prefill 阶段**：CPU 1036→1497MHz TTFT 降低 39%（102→62ms），1497→2201 几乎无变化
- **Decode 阶段**：CPU 1036→1497MHz TPOT 降低 44%（44→25ms），1497→2201 几乎无变化
- CPU 1497MHz 是两个阶段的共同饱和点

### 2.6 功耗域分解（按阶段）

| 功耗域 | Prefill | Decode | 差异 |
|--------|:---:|:---:|:---:|
| GPU SoC | 8.4W (58%) | 29.8W (74%) | +21.4W |
| CPU CV | 1.0W (7%) | 1.0W (2%) | ~0W |
| SYS 5V0 | 5.2W (36%) | 9.4W (23%) | +4.2W |
| **总计** | **14.5W** | **40.2W** | **+25.7W** |

**关键发现**：
- Decode 阶段功耗增量的 83% 来自 GPU SoC（+21.4W / +25.7W）
- CPU 功耗在两阶段完全一致（~1.0W），确认 CPU 不是推理的主要功耗来源
- SYS 5V0 在 decode 阶段增加 4.2W，可能与内存带宽增加有关

## 分析结论

### Phase-Aware DVFS 机会验证

| 阶段 | 最优 GPU 频率 | 最优 CPU 频率 | 理由 |
|------|:---:|:---:|------|
| **Prefill** | 612 MHz | 1497 MHz | TTFT 在 612MHz 饱和；CPU 1497MHz 避免调度瓶颈 |
| **Decode** | 612 MHz | 1036 MHz | TPOT 在 612MHz 饱和；低 CPU 频率降低功耗 |

### 核心规律

1. **GPU 612MHz 是两个阶段的共同最优频率**：prefill TTFT 和 decode TPOT 均在 612MHz 饱和
2. **GPU 频率饱和点一致**：不同于预期（prefill 需要高 GPU 频率，decode 不需要），实验显示两阶段均在 612MHz 饱和
3. **Decode 是功耗主体**：占推理总功耗的 73%（40.2W / 54.7W），其中 GPU SoC 贡献 83% 的阶段间功耗差异
4. **CPU 频率效应在 decode 阶段微弱**：CPU 1036→1497 MHz 功耗增加 7W 但 E/token 几乎不变
5. **Phase-Aware 的收益主要来自 CPU 侧**：prefill 用 CPU 1497MHz 避免瓶颈，decode 用 CPU 1036MHz 节能
