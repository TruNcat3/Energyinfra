# 实验 2：分阶段能耗分析

> **⚠️ 数据失效说明 (2026-05-15)**
>
> 本实验使用的 `userspace` GPU governor 存在严重 bug：在推理负载下无法锁定 GPU 频率，
> GPU 会自发跳频至 1300MHz（最大值）。这导致所有 "GPU 频率在 612MHz 饱和" 的结论是错误的。
>
> 修正后的实验（实验 3）使用 `performance` governor，证实：
> - GPU 频率对 prefill 和 decode 阶段均有显著影响（而非 612MHz 即饱和）
> - Decode 阶段 GPU SoC 功耗随频率线性增长（8→30W，而非 20→32W 持平）
> - 不同 workload 的最优 GPU 频率不同（短输出 612MHz，长输出 918MHz）
>
> **修正后的数据**见 [实验总览](实验总览.md)
>
> 本文档保留作为历史记录。阶段间功耗比例（decode 占 73%）和 CPU 频率效应部分仍有参考价值。

## 实验设计

将混合推理拆分为 prefill 和 decode 两个独立阶段分别测量：

| 阶段 | 实现方式 | 测量重点 |
|------|---------|---------|
| **prefill** | output_length=1，只生成 1 个 token | TTFT = prefill 计算延迟 |
| **decode** | prompt_length=16（最小化 prefill），output_length=64-512 | TPOT = decode 每token延迟 |

**矩阵**：4 GPU × 3 CPU × 5 workload × 2 phase × 3 repeat = 360 runs

> **注意**：部分配置（GPU612/918 × CPU1497/2201，GPU306 × CPU2201）数据缺失，
> 实际覆盖 12 个配置组合中的 8 个。

## 实验结果

### 2.1 阶段总体对比

| 指标 | Prefill | Decode | 比值 |
|------|:---:|:---:|:---:|
| TTFT (ms) | 75.3 | 31.4 | 2.4× |
| TPOT (ms) | 75.4 | 29.3 | 2.6× |
| 吞吐 (tok/s) | 27.5 | 38.5 | 0.7× |
| 功耗 (W) | 14.5 | 40.2 | 0.4× |
| E/token (J) | 7.319 | 1.178 | 6.2× |
| GPU SoC (W) | 8.4 | 29.8 | 0.3× |
| CPU CV (W) | 1.0 | 1.0 | 1.0× |
| SYS 5V0 (W) | 5.2 | 9.4 | 0.6× |

**关键发现**（仍有效）：
- Decode 阶段功耗是 prefill 的 **2.8 倍**（40.2W vs 14.5W）
- Prefill 阶段 E/token 是 decode 的 **6.2 倍**（7.319J vs 1.178J）
- 两阶段 CPU 功耗几乎相同（~1.0W），说明 CPU 不是功耗差异来源

> ⚠️ GPU SoC 功耗数据受 governor bug 影响。实际 decode GPU SoC 功耗范围应为 8-30W（随频率变化），
> 而非本表中显示的固定 ~30W。

### 2.6 功耗域分解（按阶段）

| 功耗域 | Prefill | Decode | 差异 |
|--------|:---:|:---:|:---:|
| GPU SoC | 8.4W (58%) | 29.8W (74%) | +21.4W |
| CPU CV | 1.0W (7%) | 1.0W (2%) | ~0W |
| SYS 5V0 | 5.2W (36%) | 9.4W (23%) | +4.2W |
| **总计** | **14.5W** | **40.2W** | **+25.7W** |

**关键发现**（仍有效）：

- CPU 功耗在两阶段完全一致（~1.0W）

## 分析结论

> ⚠️ 以下第 1、2、5 条关于 GPU 频率的结论已失效

### Phase-Aware DVFS 机会验证

| 阶段 | 最优 GPU 频率 | 最优 CPU 频率 | 理由 |
|------|:---:|:---:|------|
| **Prefill** | ~~612 MHz~~ | 1497 MHz | CPU 1497MHz 避免调度瓶颈（仍有效） |
| **Decode** | ~~612 MHz~~ | 1036 MHz | 低 CPU 频率降低功耗（仍有效） |

### 核心规律

1. ~~GPU 612MHz 是两个阶段的共同最优频率~~ → 修正：GPU 918MHz 在长输出中更优
2. ~~GPU 频率饱和点一致~~ → governor bug 所致
3. **Decode 是功耗主体**：占推理总功耗的 73%（仍有效）
4. **CPU 频率效应在 decode 阶段微弱**（仍有效，量化数值基于修正前数据）
5. ~~Phase-Aware 的收益主要来自 CPU 侧~~ → 修正：GPU 侧频率调节也有显著收益
