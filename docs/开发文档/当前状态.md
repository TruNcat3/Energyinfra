### P6: GPU Governor Bug 修复与扩展实验 (已完成 2026-05-15)

**发现**：GPU devfreq `userspace` governor 在推理负载下无法锁定频率，GPU 自发跳频至 1300MHz。
所有 "GPU 频率无影响" 的结论是此 bug 导致的错误结论。

**修复**：改用 `performance` governor，可靠锁定 GPU 频率。

**扩展实验**：
- 实验矩阵：4 GPU × 2 CPU × 14 workloads × 2 phases × 3 repeats = **672 runs**
- 数据文件：`data/energy_profiling/expanded_profiling_20260515_031015.csv`

**修正后核心发现**：

| GPU 频率 | Decode TPS (CPU=1036) | GPU SoC 功耗 |
|:---:|:---:|:---:|
| 306 MHz | ~12 tok/s | ~8 W |
| 612 MHz | ~23 tok/s | ~13 W |
| 918 MHz | ~30 tok/s | ~19 W |
| 1300 MHz | ~41 tok/s | ~30 W |

**GPU 频率对性能有显著影响（306→918 MHz：TPS 提升 2.5×）**

## 技术风险和限制

1. **GPU Governor 兼容性**: `userspace` governor 在推理负载下不可靠，必须使用 `performance` governor
2. **频率控制精度**: sysfs读取频率可能有延迟
3. **模型单一性**: 仅验证Phi-3-mini，需扩展到其他模型
4. **热效应**: 长时间运行的thermal throttling未建模
5. **数据可靠性**: 扩展实验中 GPU918_CPU1497 配置不可靠（577/659 有效 = 88%）
