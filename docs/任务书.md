# 任务书：Jetson LLM 能耗汇率表与自适应配置选择机制

## 项目目标

### 核心目标
构建面向 Jetson 边端 GPU 的 LLM 推理能耗 profiling 与自适应配置选择系统，实现：

1. **能耗汇率表构建**：建立 workload-aware 的能耗汇率表，将不同负载在不同频率配置下的性能、功耗和能耗关系显式记录
2. **自适应配置选择**：设计 SLO-aware 的配置选择器，在满足时延、功耗、温度约束的前提下，使推理过程尽可能降低 energy/token
3. **在线控制系统**：实现可离线建表、在线查表、自动选频的系统，支持在推理服务中周期性选择和应用配置

### 技术目标

**面向平台**：Jetson Orin 等边端 GPU 平台

**关键技术**：
- GPU/CPU/EMC 频率自适应调节
- Prefill/Decode 分阶段 DVFS
- Workload-aware 能效优化
- SLO-aware 配置选择

**预期贡献**：
1. 系统性刻画 Jetson 边端 GPU 上 LLM 推理的频率—性能—能耗行为
2. 提出 workload-aware energy rate table，将收益和代价表示为汇率形式
3. 设计 SLO-aware adaptive DVFS selector，实现能效最优运行点选择

## 研究方向

### 核心研究问题

1. **测量稳定性**：Jetson 边端 GPU 上的 LLM 推理是否存在稳定的频率—性能—能耗关系
2. **旋钮作用差异**：GPU、CPU 和 EMC 频率对不同指标的影响是否不同
3. **负载差异**：不同 workload 是否具有不同的最优配置
4. **分阶段策略**：Prefill 和 decode 阶段是否应该采用不同配置
5. **可预测性**：能否用简单的 workload feature 预测最优配置

### 技术路线

**四个阶段**：

1. **离线频率扫描**：枚举不同 workload 和频率配置，记录性能、功耗和温度指标
2. **能耗汇率表构建**：计算派生指标，保留非支配配置，形成 Pareto frontier
3. **负载感知配置选择**：根据 workload feature 查表或调用轻量模型得到推荐配置
4. **在线控制与稳定机制**：在推理过程中应用选定配置，避免频繁切换导致抖动

## 目标指标

### 功能指标
- [ ] 支持 GPU/CPU/EMC 频率的读取、设置和恢复
- [ ] 自动执行 workload × frequency sweep，采集性能、功耗和温度数据
- [ ] 构建能耗汇率表，支持多维度指标查询
- [ ] 实现 SLO-aware 配置选择器
- [ ] 支持 prefill/decode 分阶段策略
- [ ] 提供可视化分析工具

### 性能指标
- [ ] 相比 MaxN 全拉满策略，在满足 SLO 的前提下降低 energy/token
- [ ] 相比默认 governor 策略，降低尾延迟或提升 tokens/J
- [ ] 相比固定 best-efficiency 策略，在 workload 变化时具有更稳定的性能表现
- [ ] 测量稳定性：energy/token 和 latency 的标准差较小（< 5%）

### 质量指标
- [ ] 可重复性：同一配置重复运行结果稳定
- [ ] 准确性：预测模型具有较高的预测精度
- [ ] 可靠性：在线控制器能够处理异常情况，提供安全回退
- [ ] 可扩展性：支持多种 LLM runtime 和 Jetson 型号

## 当前开发策略

### 第一阶段：前置验证实验
**目标**：确定可能的优化空间，验证核心假设

**7个前置实验**：
1. **测量稳定性实验**：验证同一 workload 和同一频率配置下，测量结果是否稳定
2. **单旋钮敏感性实验**：区分 GPU、CPU 和 EMC 频率对不同指标的影响
3. **频率组合交互实验**：验证最优配置是否来自多个频率旋钮的组合
4. **Prefill/Decode 分阶段实验**：验证 phase-aware DVFS 的必要性
5. **负载特征可预测性实验**：验证能否根据 workload feature 预测最优配置
6. **频率切换开销实验**：确认在线调频是否会引入不可忽略的开销
7. **SLO 约束下的端到端实验**：证明本任务不是离线调参，而是一个实际可用的服务策略

### 第二阶段：完整系统实现
**目标**：基于前置实验的验证结果，构建完整的系统

**5个核心模块**：
1. **频率控制模块**：GPU/CPU/EMC 频率的读取、设置和恢复
2. **负载运行模块**：执行 LLM 推理 benchmark
3. **指标采集模块**：采集性能、功耗、温度数据
4. **汇率表构建模块**：计算派生指标，提取 Pareto frontier
5. **配置选择器模块**：根据 workload 和 SLO 选择最优配置

### 第三阶段：在线控制与优化
**目标**：实现在线控制器，支持推理服务中的实时配置选择

**关键机制**：
- Hysteresis 机制：避免频繁切换
- 边界切换：优先在 phase boundary 处切换
- 安全回退：监控温度和实际 latency，出现偏差时回退到安全配置

## 成功标准

### 验收标准

**前置实验验证**：
1. 系统能够在固定 workload 和固定频率配置下重复运行，并输出稳定的统计结果
2. 系统能够完成 GPU、CPU 和 EMC 单旋钮 sweep，并生成对应 heatmap
3. 系统能够完成频率组合实验，并自动提取 Pareto frontier
4. 系统能够区分 prefill-heavy 和 decode-heavy 场景，并验证二者的能效最优配置是否不同
5. 系统能够根据 workload feature 和 SLO 约束输出推荐配置

**完整系统验收**：
6. 相比 MaxN 或 jetson_clocks 全拉满策略，系统应在满足 SLO 的前提下降低 energy/token
7. 相比固定低功耗策略，系统应在重负载或长 decode 场景下避免明显 P99 latency 退化

### 决策点

基于前置实验的结果，确定：

- 如果优化空间存在 → 继续实现完整的汇率表和选择器
- 如果优化空间有限 → 调整策略或缩小范围
- 如果出现技术障碍 → 先解决技术问题再继续

## 风险与限制

### 主要风险

1. **测量稳定性**：如果同一配置下测量结果波动很大，能耗汇率表无法可靠使用
2. **频率控制权限**：某些 Jetson 设备可能需要 root/sudo 权限才能设置频率
3. **热效应影响**：长时间运行可能导致热降频，影响测量稳定性
4. **运行时工具兼容性**：不同 JetPack 版本的 tegrastats 输出格式可能不同

### 主要限制

1. **硬件限制**：仅支持 Jetson 系列 GPU，不适用于其他平台
2. **运行时限制**：初期主要支持 TensorRT-LLM，其他运行时需要额外适配
3. **模型限制**：初期主要测试中小型模型（如 Qwen-7B），大型模型可能需要更长时间
