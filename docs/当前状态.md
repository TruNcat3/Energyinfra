**平台**: Jetson AGX Orin (MAXN mode)

#### GPU 频率对性能无影响 (Memory-Bound 确认)

| GPU 频率 | CPU 频率 | TTFT (ms) | TPOT (ms) | 吞吐量 (tok/s) |
|----------|----------|-----------|-----------|---------------|
| 306 MHz | 2201 MHz | 773.8 | 107.6 | 9.0 |
| 612 MHz | 2201 MHz | 889.7 | 104.7 | 9.1 |
| 918 MHz | 2201 MHz | 430.8 | 105.2 | **9.4** |
| 1300 MHz | 2201 MHz | 498.7 | 107.0 | 9.2 |

> **GPU频率从 306→1300 MHz (4.25倍)，吞吐量仅提升 1.01x — 确认 LLM 推理是 Memory-Bound**

#### CPU 频率是性能瓶颈

| CPU 频率 | TTFT (ms) | TPOT (ms) | 吞吐量 (tok/s) |
|----------|-----------|-----------|---------------|
| 1036 MHz | 870.8 | 200.9 | 4.9 |
| 1497 MHz | 564.5 | 144.9 | 6.9 |
| 2201 MHz | 642.8 | 106.2 | **9.2** |

> **CPU频率从 1036→2201 MHz (2.12倍)，吞吐量提升 1.86x — CPU 是主要瓶颈**

#### 关键发现

| 指标 | 数值 | 含义 |
|------|------|------|
| GPU freq scaling | 1.01x | GPU 频率对吞吐量几乎无影响 |
| CPU freq scaling | **1.86x** | CPU 频率是性能的决定性因素 |
| 最优配置 | GPU918+CPU2201 = 9.4 tok/s | 最高 GPU 频率并非最优 |
| TTFT CPU 效果 | -26.2% | 高 CPU 频率显著降低首token延迟 |
| TTFT GPU 效果 | -0.8% | GPU 频率对 TTFT 无显著影响 |
| 零token异常 | 35/180 (19.4%) | 长prompt低频首次推理偶发，已过滤 |

## 技术风险和限制

1. **零token异常率 19.4%**: 长prompt低频首次推理容易产生0输出，需增加warmup或retry机制
2. **频率控制精度**: sysfs读取频率可能有延迟
3. **模型单一性**: 仅验证Phi-3-mini，需扩展到其他模型
4. **热效应**: 长时间运行的thermal throttling未建模
5. **CPU瓶颈**: 真实模型实验确认CPU是性能瓶颈，GPU节能空间大但CPU不可降频
