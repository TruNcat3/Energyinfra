#### 1. ✅ 使用所有频率档位进行对比
**更新内容**：
- 新增 `configs/workloads_updated.yaml` 配置文件
- 包含所有 13 个 Jetson Orin GPU 频率档位（从 378MHz 到 1428MHz）
- 10 个 CPU 频率档位（从 1020MHz 到 2015MHz）
- 7 个 EMC 频率档位（从 133MHz 到 2133MHz）
- 总计 30 个频率档位（远超原来的 low/mid/high 三档）

**实验配置更新**：
- 单旋钮敏感性实验：使用所有 10 个 GPU 频率、10 个 CPU 频率、7 个 EMC 频率
- 频率组合实验：使用代表性档位（低/中/高）
- Phase 差异实验：使用所有 GPU 频率档位进行对比

#### 2. ✅ 能效对比逻辑优化
**更新内容**：
- 核心要求：只在满足 SLO 的条件下进行能效对比
- 不满足 SLO 的点应该在对比中被去除
- 避免不公平的比较：确保所有参与对比的配置都满足基本的 SLO 约束

**实现策略**：
1. 硬约束设置：TTFT < 1000ms, TPOT < 80ms, P99 < 150ms
2. 软约束设置：功耗 < 50W, 温度 < 80°C
3. 配置过滤：只比较满足所有硬约束的配置
4. 数据可视化：在图表中标注 SLO 违反点
5. 分析报告生成：明确标注哪些配置满足/不满足 SLO

**预期效果**：
- 更加公平和准确的能效评估
- 清晰展示哪些配置在实际应用中可行（满足 SLO）
- 更好地指导系统设计和优化方向

#### 3. ✅ 尝试阶段3：全面频率档位分析
**阶段3 目标**：使用所有频率档位进行对比，分析能效表现

**新增实验配置**：
```yaml
phase_3_full_frequency_analysis:
  model: "qwen-7b-int4"
  batch_size: 1
  prompt_len: 512
  output_len: 128
  phase: "mixed"
  concurrency: 1
  repeats: 3

  # 使用所有频率档位（代表性采样以控制实验规模）
  gpu_freqs: [378, 513, 624, 729, 846, 936, 1065, 1152, 1242, 1308, 1428]  # 13 个档位
  cpu_freqs: [1020, 1152, 1200, 1479, 1632, 1764, 1908, 2015]
  emc_freqs: [133, 800, 1066, 1333, 1600, 1866, 2133] # 7 个档位

  total_configs: 13 * 10 * 7 = 910  # 13 GPU × 10 CPU × 7 EMC
```

**采样策略**：
- 使用所有档位进行对比可能过于庞大（910 个配置）
- 建议采用分层采样：
  - 第 1 轮：主要档位（低/中/高）的组合 = 27 个配置
  - 第 2 轮：在每个主要档位附近扩展 1-2 个档位

**分析重点**：
- 不同档位的能效表现曲线
- 性能 vs 功耗的权衡关系
- 最优操作点识别
- SLO 约束下的最优配置
